# usque на OpenWrt: установка и интерфейс `usque`

Для OpenWrt собираются два пакета (`.ipk`):

| Пакет | Что делает |
|-------|------------|
| `usque_<версия>_<арх>_openwrt.ipk` | Сам клиент `/usr/bin/usque` + служба `/etc/init.d/usque` (SOCKS5 / HTTP-прокси / nativetun, настройка через `/etc/config/usque`). |
| `usque-proto_<версия>_all.ipk` | Протокол **`usque`** для netifd: WARP как обычный сетевой интерфейс OpenWrt (`network.<имя>.proto='usque'`) с настройкой в LuCI и UCI. Нужен установленный `usque`. |

Пакет `usque-proto` не зависит от архитектуры (`all`), `usque` нужно выбрать под ваш роутер.

## 1. Какой пакет `usque` выбрать

Выполните на роутере:

```sh
opkg print-architecture
```

| Архитектура OpenWrt | Суффикс пакета |
|---------------------|----------------|
| `x86_64` | `amd64` |
| `aarch64_*` | `arm64` |
| `arm_cortex-a*` (a7, a9, a15) | `armv7` |
| `arm_arm926ej-s`, `arm_arm1176jzf-s_vfp` и другие ARMv5/ARMv6 | `armv5` |
| `mipsel_*` (mipsel_24kc, mipsel_74kc …) | `mipsle` |
| `mips_*` (mips_24kc, mips_74kc …) | `mips` |
| `mips64_*` | `mips64` |
| `mips64el_*` | `mips64le` |

## 2. Установка

Скачайте нужные `.ipk` из релиза репозитория и скопируйте на роутер:

```sh
scp usque_*_<арх>_openwrt.ipk usque-proto_*_all.ipk root@192.168.1.1:/tmp/
```

На роутере:

```sh
opkg update
opkg install kmod-tun            # TUN нужен для режима интерфейса
opkg install /tmp/usque_*_openwrt.ipk
opkg install /tmp/usque-proto_*_all.ipk
/etc/init.d/network restart       # netifd подхватит новый протокол
```

> `ip` (пакет `ip-tiny` или `ip-full`) в обычных сборках OpenWrt уже есть. Если нет: `opkg install ip-full`.

## 3. Регистрация в Cloudflare WARP

Один раз создайте конфиг (ключ устройства и адреса тоннеля):

```sh
mkdir -p /etc/usque
usque -c /etc/usque/config.json register
```

Если `register` не отвечает из вашей сети, выполните его на другом компьютере или через другой канал и скопируйте получившийся `config.json` в `/etc/usque/`.

## 4. Интерфейс WARP (netifd)

### Через LuCI

1. **Network → Interfaces → Add new interface…**
2. Имя: `warp` (не длиннее 9 символов), протокол: **Cloudflare WARP (usque / MASQUE)**.
3. В верхней части окна интерфейса находится **панель состояния**:
   - состояние (подключено / подключаюсь / остановлено);
   - **к какому серверу, порту и по какому протоколу идёт подключение**, SNI и адрес в тоннеле;
   - кнопки **Старт, Стоп, Перезапуск, Обновить** (Стоп работает всегда, даже если интерфейс завис в ошибке);
   - **«Зарегистрировать»**, если файла настроек WARP ещё нет, и «Перерегистрация» (старый конфиг сохраняется как `.bak`);
   - раскрывающийся **журнал usque**, где видно, почему не подключилось.
4. Ниже выберите **Способ подключения** (по умолчанию «Авто»), при необходимости порт, SNI и адрес сервера. Подробности в разделе 4.1.
5. На вкладке *Firewall Settings* привяжите интерфейс к зоне (см. раздел 5).
6. **Save & Apply**.

> Родная кнопка **Stop** в списке интерфейсов LuCI неактивна, пока интерфейс не поднят. Это поведение самого LuCI, и пакет его не меняет. Используйте кнопку «Стоп» в панели внутри окна интерфейса.

Если панель показывает «Панель недоступна», выполните `/etc/init.d/rpcd restart` и войдите в LuCI заново (rpcd читает плагины только при запуске).

### 4.1. Настройка обхода блокировок (ТСПУ)

Весь трафик MASQUE идёт к Cloudflare. ТСПУ (российский DPI) умеет резать QUIC (UDP), порт 443, стандартный SNI и адреса WARP. Поэтому usque умеет **клиентский обход**: он ничего не меняет ни в протоколе MASQUE, ни на сервере Cloudflare — только подбирает такую комбинацию адреса, порта, SNI и транспорта, которая проходит через конкретную сеть.

| Способ | Что делает |
|--------|------------|
| **Авто** (по умолчанию) | Включает обход ТСПУ (`usque nativetun --bypass`). usque перебирает комбинации «в ширину»: транспорт, порты, SNI и адреса Cloudflare чередуются, поэтому рабочая находится за первые десятки секунд. Победителя держит в памяти и предпочитает при переподключении. |
| QUIC / HTTP/3 (UDP) | Только QUIC, порт из поля «Порт сервера» (по умолчанию 443). |
| HTTP/2 (TCP 443) | Только HTTP/2 по TCP. Подходит, когда режется UDP. |
| Вручную | Берутся флаг `http2` и порт из полей ниже. |
| + галочка **«Обход ТСПУ и для выбранного способа»** | Добавляет перебор к явному способу выше (QUIC/HTTP/2/вручную): usque сам пробует и остальные порты, и SNI, и адреса сервера. |

Как именно обходится DPI:
- **перебор адресов и портов Cloudflare** — если ТСПУ блокирует адрес или порт, пробуется следующий;
- **перебор SNI** — имена вне Cloudflare (`www.microsoft.com`, `www.apple.com`, `www.bing.com`) идут первыми, затем имена Cloudflare (`one.one.one.one`, `www.cloudflare.com`, `zt-masque.cloudflareclient.com`, `consumer-masque.cloudflareclient.com`). Порядок такой потому, что сервер принимает любое имя, а ТСПУ режет домены Cloudflare по SNI;
- **дробление TLS ClientHello** (для HTTP/2) — сегменты делятся **в середине имени сервера**, поэтому DPI видит не цельный шаблон, а обрывок SNI;
- **несколько попыток одновременно** — по умолчанию три, поэтому перебор идёт примерно втрое быстрее (каждая заблокированная комбинация иначе съедала бы полный таймаут);
- **безопасный первый QUIC-пакет** (1200 байт) — отключает PMTU-зондирование крупными пакетами, которые ТСПУ часто роняет молча.

> Если провайдер блокирует **домены Cloudflare** по SNI (обычно вместе с `cloudflareclient.com`), встроенные имена не помогут. Укажите своё незаблокированное имя в поле **«Свои SNI для обхода»** (опция `bypass_sni`, через пробел или запятую). Сервер не проверяет имя: сертификат привязывается к открытому ключу эндпоинта, поэтому подходит любой домен. Пример: `bypass_sni='www.example.com'`. Это работает и для QUIC, и для HTTP/2.

Порты UDP 443 (основной), 500, 1701, 4500, 4443, 8443, 8095 и TCP 443 для HTTP/2 указаны в документации Cloudflare ([WARP with firewall](https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/cloudflare-one-client/deployment/firewall/)); адреса MASQUE: `162.159.197.0/24`. Запасные диапазоны: `162.159.192.0/24`, `162.159.193.0/24`, `162.159.195.0/24`, `162.159.198.0/24`, `162.159.204.0/24` (IPv4) и `2606:4700:102::/48` (IPv6).

Поля, которые можно менять:
- **Порт сервера:** выпадающий список портов или своё значение. В обходе пробуется первым.
- **SNI:** имя в TLS-рукопожатии. Пусто — в обходе перебирается автоматически (сначала имена вне Cloudflare, затем имена Cloudflare). Готовые варианты: `www.microsoft.com`, `www.apple.com`, `www.bing.com`, `consumer-masque.cloudflareclient.com` (стандартный), `zt-masque.cloudflareclient.com` (рекомендует автор usque), `www.cloudflare.com`, `one.one.one.one`. Если задать своё имя, перебор SNI отключается.
- **Адрес сервера (QUIC)** и **Адрес сервера (HTTP/2)**: IP-адреса вместо взятых из `config.json`. Пусто означает «из config.json» (для HTTP/2 по умолчанию `162.159.198.2`); в обходе они пробуются первыми, затем запасные.
- **Дополнительные аргументы (`args`)**: сюда можно передать любые флаги usque, например `args '--bypass-parallel 5 --connect-timeout 3'` (больше одновременных попыток и короче таймаут — перебор быстрее, но заметнее для DPI) или `args '--tls-fragment-sizes 1 2'` для явного дробления ClientHello.

> При `defaultroute=1` режим обхода автоматически добавляет маршруты до подсетей Cloudflare (`162.159.192.0/24`, `162.159.193.0/24`, `162.159.195.0/24`, `162.159.197.0/24`, `162.159.198.0/24`, `162.159.204.0/24`, `2606:4700:102::/48`) через прежний шлюз. Иначе после подъёма тоннеля перебор адресов ушёл бы сам в себя. Маршруты снимаются при остановке интерфейса. Если задаёте свои адреса через `args` (`--bypass-endpoint`) вне этих подсетей, добавьте маршрут до них сами.

> Какая комбинация проходит через вашего провайдера, заранее сказать нельзя: это зависит от сети и со временем меняется. Режим «Авто» нужен как раз для того, чтобы подобрать её на месте. Если ничего не подошло, пришлите содержимое журнала, и по нему можно понять, где обрывается соединение.

#### Кнопка «Проверить»

В панели состояния (вкладка **Основные** интерфейса) есть кнопка **«Проверить»**: она запускает `usque check` — тот же перебор комбинаций, что и режим «Авто», но без поднятия интерфейса. TUN-устройство не создаётся, адреса и маршруты не трогаются. Несколько комбинаций проверяются одновременно (по умолчанию три), поэтому результат появляется в панели за десятки секунд: какая комбинация (адрес, порт, SNI, транспорт) сработала либо список проваленных попыток.

Ту же проверку можно выполнить вручную, в том числе вне роутера:

```sh
usque -c /etc/usque/config.json check --bypass
usque -c /etc/usque/config.json check --bypass --bypass-sni www.example.com
usque -c /etc/usque/config.json check --bypass --all                # проверить все комбинации
usque -c /etc/usque/config.json check --bypass --bypass-parallel 5  # больше попыток одновременно
```

Код возврата `0`, если хотя бы одна комбинация подключилась. Проверка не заменяет запуск интерфейса — она только подсказывает рабочие параметры (их можно перенести в поля выше или в `bypass_sni`).

### Через UCI

```sh
uci set network.warp=interface
uci set network.warp.proto='usque'
uci set network.warp.config='/etc/usque/config.json'
uci set network.warp.profile='auto'
uci set network.warp.sni='zt-masque.cloudflareclient.com'
uci commit network
ifup warp
```

Проверка:

```sh
ifstatus warp
ip addr show usque-warp
cat /var/run/usque/warp.log      # журнал usque (в RAM)
logread -e usque                  # сообщения netifd-протокола
```

Устройство называется `usque-<имя интерфейса>` (до 15 символов).

### Параметры интерфейса

| Опция UCI | По умолчанию | Описание |
|-----------|--------------|----------|
| `config` | `/etc/usque/config.json` | Конфиг, созданный командой `usque register`. |
| `profile` | `auto` | Способ подключения: `auto`, `quic`, `h2`, `manual` (см. 4.1). `auto` включает обход ТСПУ. |
| `connect_port` | `443` | Порт сервера. В обходе пробуется первым. |
| `sni` | по умолчанию usque | Свой SNI. Если задан, перебор SNI отключается. |
| `endpoint` | из config.json | IP сервера для QUIC. В обходе пробуется первым. |
| `endpoint_h2` | из config.json | IP сервера для HTTP/2. В обходе пробуется первым. |
| `http2` | `0` | Только для `profile=manual`: `1` — HTTP/2 вместо QUIC. |
| `ipv6` | `0` | `1` — подключаться к серверу по IPv6. |
| `bypass` | `0` | `1` — включить обход ТСПУ и для явного способа `quic`/`h2`/`manual` (в `auto` обход включён всегда). |
| `bypass_sni` | пусто | Свой список SNI через пробел или запятую. Полностью заменяет встроенный. Нужен, когда провайдер блокирует домены Cloudflare по имени. |
| `defaultroute` | `1` | Общая опция LuCI «Use default gateway»: `1` — весь трафик роутера через WARP (маршруты до серверов Cloudflare добавляются через прежний шлюз автоматически), `0` — маршруты задаёте сами. |
| `dns` | не задан | Общая опция LuCI «Use custom DNS servers». |
| `mtu` | `1280` | MTU тоннеля (менять не рекомендуется). |
| `tunnel_ipv4` / `tunnel_ipv6` | `1` / `1` | Выдавать ли внутри тоннеля IPv4 / IPv6-адрес. |
| `keepalive` | `30s` | Период keepalive. |
| `reconnect_delay` | `1s` | Пауза между попытками переподключения. |
| `initial_packet_size` | авто (в обходе `1200`) | Размер первого пакета. |
| `insecure` | `0` | Не проверять сертификат сервера (только для отладки). |
| `connect_timeout` | `90` (обход), `20` (остальные) | Сколько всего секунд ждать, пока тоннель поднимется. |
| `args` | пусто | Дополнительные аргументы для `usque nativetun` (например, `--bypass-endpoint <ip>`). |

## 5. Файрвол и маршрутизация

Чтобы клиенты LAN выходили в интернет через WARP, создайте зону для интерфейса:

```sh
uci add firewall zone
uci set firewall.@zone[-1].name='warp'
uci set firewall.@zone[-1].network='warp'
uci set firewall.@zone[-1].input='REJECT'
uci set firewall.@zone[-1].output='ACCEPT'
uci set firewall.@zone[-1].forward='REJECT'
uci set firewall.@zone[-1].masq='1'
uci set firewall.@zone[-1].mtu_fix='1'
uci add firewall forwarding
uci set firewall.@forwarding[-1].src='lan'
uci set firewall.@forwarding[-1].dest='warp'
uci commit firewall
/etc/init.d/firewall restart
```

Какой трафик идёт в тоннель, решает маршрутизация:

- **Весь трафик** — по умолчанию (`defaultroute='1'`).
- **Только нужные сети** — оставьте `defaultroute='0'` и добавьте статический маршрут:
  ```sh
  uci add network route
  uci set network.@route[-1].interface='warp'
  uci set network.@route[-1].target='203.0.113.0/24'
  uci commit network && /etc/init.d/network reload
  ```
- **По источнику (отдельные устройства)** — политика маршрутизации (`pbr`, `mwan3` или `ip rule`) с таблицей, в которой маршрут по умолчанию идёт на `usque-warp`.

Сам usque маршруты не расставляет, в режиме интерфейса это делает netifd.

## 6. Служба `usque` (без интерфейса)

Пакет `usque` также содержит независимую службу (SOCKS5 / HTTP-прокси / nativetun), настройка в `/etc/config/usque`:

```sh
uci set usque.main.enabled=1 && uci commit usque
/etc/init.d/usque enable && /etc/init.d/usque start
```

Не включайте службу и интерфейс `usque` одновременно на одном `config.json`: оба будут занимать одно устройство WARP.

## 7. Если не работает

| Симптом | Что проверить |
|---------|---------------|
| В LuCI нет протокола `usque` | `/etc/init.d/network restart`, очистить кэш браузера. |
| Панель состояния пишет «недоступна» | `/etc/init.d/rpcd restart`, затем войти в LuCI заново. |
| `NO_TUN` в `logread` | `opkg install kmod-tun`, затем `modprobe tun`. |
| `NO_CONFIG` | Файл из опции `config` не существует: выполните `usque ... register`. |
| `CONNECT_TIMEOUT` | Ни один способ не подключился. Откройте журнал в панели интерфейса (или `/var/run/usque/<имя>.log`). Проверьте `profile=auto` (обход ТСПУ), другой SNI, адрес сервера, увеличьте `connect_timeout`. |
| Интерфейс поднят, трафика нет | Зона файрвола, маршруты (`ip route`, `ip rule`), `masq` на зоне `warp`. |
| Пропал интернет после `defaultroute=1` | Проверьте маршрут до эндпоинта: `ip route get <endpoint_v4 из config.json>` должен идти через WAN, а не через `usque-warp`. |

## 8. Удаление

```sh
ifdown warp
uci delete network.warp && uci commit network
opkg remove usque-proto usque
```
