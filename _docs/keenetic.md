# usque на Keenetic (OPKG / Entware): установка и служба

Для Keenetic собирается один пакет — `usque_<версия>_<арх>_keenetic.ipk`:

| Что внутри | Куда ставится |
|------------|---------------|
| Клиент `usque` | `/opt/bin/usque` |
| Служба `S99usque` (SOCKS5, L4-прокси, HTTP-прокси, nativetun) | `/opt/etc/init.d/S99usque`, настройки — `/opt/etc/usque/usque.conf` |

В релизах лежат и отдельные бинарники `usque_<версия>_linux_<арх>` — те же самые, что внутри пакетов (для запуска без `opkg`).

Нужен установленный на роутере компонент **OPKG** с репозиторием **Entware**: он монтирует накопитель в `/opt` и запускает скрипты оттуда. Если Entware ещё нет, установите его по инструкции Keenetic («Установка репозитория Entware на USB-накопитель» или «Установка OPKG Entware во внутреннюю память»).

## 1. Какой пакет выбрать

Выполните на роутере:

```sh
opkg print-architecture
```

| Архитектура в выводе | Суффикс пакета | Обычно это |
|----------------------|----------------|------------|
| `mipsel-3.4` | `mipselsf` | большинство Keenetic на MT7621/MT7628/MT7620 — например, Giga (KN-1010) и Ultra (KN-1810) |
| `mips-3.4` | `mipssf` | старые MIPS big-endian |
| `armv5-3.2` | `armv5sf` | старые ARMv5 |
| `armv7-3.2` | `armv7sf` | ARMv7 soft-float |
| `aarch64-3.10` | `aarch64` | Hero (KN-1012), Peak (KN-2710) и другие новые модели |

Если сомневаетесь — вспомните, какой установщик Entware вы запускали: `mipsel-installer.tar.gz` → `mipselsf`, `aarch64-installer.tar.gz` → `aarch64`, `mips-installer.tar.gz` → `mipssf`.

Бинарники собраны с мягкой плавучкой (`GOMIPS=softfloat`, `GOARM=5`) — так же, как пакеты самой Entware, поэтому подходят к её федам `mipsel-3.4`, `mips-3.4`, `armv5-3.2`, `armv7-3.2`.

## 2. Установка

Скачайте нужный `.ipk` из релиза и скопируйте на роутер:

```sh
scp usque_*_mipselsf_keenetic.ipk root@192.168.1.1:/tmp/
```

На роутере установите его одним из способов:

```sh
opkg install /tmp/usque_*_keenetic.ipk
```

или штатным механизмом Keenetic — положите `.ipk` в папку `install` на накопителе (`/opt/install/`) и перезагрузите роутер: OPKG-компонент сам распакует его в `/opt`.

> `opkg install` перезапишет службу и бинарник, но оставит ваши `/opt/etc/usque/usque.conf` и `config.json` (файл настроек службы помечен как conffile).

## 3. Регистрация в Cloudflare WARP

Один раз создайте конфиг (ключ устройства и адреса тоннеля):

```sh
mkdir -p /opt/etc/usque
usque -c /opt/etc/usque/config.json register
```

Если `register` не отвечает из вашей сети, выполните его на другом компьютере или через другой канал и скопируйте получившийся `config.json` в `/opt/etc/usque/`.

## 4. Служба `S99usque`

Настройки — `/opt/etc/usque/usque.conf`:

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `ENABLED` | `1` | `1` — запускать службу (в том числе при загрузке), `0` — не запускать. |
| `MODE` | `socks` | `socks` — SOCKS5 (TCP+UDP), `l4-socks` — SOCKS5 только TCP (легче и быстрее), `http-proxy`, `l4-http-proxy`, `nativetun` — TUN-интерфейс. |
| `BIND` | `127.0.0.1` | Адрес прослушивания в прокси-режимах. `0.0.0.0` — доступ из локальной сети. |
| `PORT` | `1080` | Порт прослушивания. |
| `CONFIG` | `/opt/etc/usque/config.json` | Конфиг, созданный командой `usque register`. |
| `ARGS` | `--bypass` | Любые дополнительные флаги `usque` (см. раздел 5). |

Управление и журнал:

```sh
/opt/etc/init.d/S99usque start      # или stop | restart | status
tail -f /opt/var/log/usque.log      # журнал службы
```

**Автозапуск.** OPKG-компонент Keenetic при подключении накопителя выполняет скрипты из `/opt/etc/init.d/` с аргументом `start` (если у вас нет своего `/opt/etc/initrc`), а при извлечении — с аргументом `stop`. Пакет уже кладёт туда `S99usque`, поэтому отдельно автозапуск настраивать не нужно: достаточно один раз выполнить `register` — и служба поднимется сама, и после каждой перезагрузки тоже.

Проверка, что всё поднялось:

```sh
/opt/etc/init.d/S99usque status
ps | grep '[u]sque'
curl -x socks5h://127.0.0.1:1080 https://cloudflare.com/cdn-cgi/trace   # если установлен curl (opkg install curl)
```

> Для режима `nativetun` задайте имя интерфейса в `ARGS` (например, `ARGS="-n usque0 --bypass"`), а маршруты прописывайте сами. Для простых задач на Keenetic обычно удобнее прокси-режимы: TUN-интерфейс придётся вручную раздавать в LAN маршрутами.

## 5. Обход ТСПУ

Пакет устанавливается с включённым обходом: `ARGS="--bypass"`. Что это и как работает — в [`_docs/openwrt.md`](openwrt.md#41-настройка-обхода-блокировок-тспу) (раздел 4.1), вся логика одинаковая на любом устройстве.

Проверить, какая комбинация проходит именно у вашего провайдера:

```sh
usque -c /opt/etc/usque/config.json check --bypass
usque -c /opt/etc/usque/config.json check --bypass --bypass-sni www.example.com
```

Полезное в `ARGS`:

- `--bypass-sni www.example.com` — если провайдер блокирует домены Cloudflare по SNI: сервер принимает любое имя, поэтому подойдёт свой незаблокированный домен;
- `--bypass-parallel 5` и `--connect-timeout 3` — перебор идёт быстрее (заметнее для DPI);
- `--tls-curve p256` — маленькое TLS-рукопожатие (~300 байт вместо ~1.7 КБ);
- `--bypass-state -` — не запоминать рабочую комбинацию на диске.

Удачная комбинация сохраняется рядом с `config.json` (файл `config.json.bypass`) и пробуется первой после перезагрузки. Файл можно удалить, чтобы перебор начался заново.

## 6. Как пустить через WARP трафик роутера и сети

- **Прокси для отдельных устройств.** Поставьте `BIND=0.0.0.0`, перезапустите службу и укажите на клиентах SOCKS5-прокси `192.168.1.1:1080` (адрес роутера в домашней сети).
- **Proxy client самого Keenetic.** В веб-интерфейсе: *Интернет → Другие подключения → Proxy client* — укажите SOCKS5-прокси `192.168.1.1:1080` (при `BIND=0.0.0.0`). Дальше через это подключение можно направить весь трафик роутера или отдельные устройства — политиками подключений. Keenetic проксирует TCP; UDP через такой Proxy client не пойдёт (для UDP нужны `socks`/`nativetun` и маршруты).
- **TUN-интерфейс.** `MODE=nativetun` создаёт в системе интерфейс (имя из `ARGS`, например `usque0`). Он не добавляется в LAN сам по себе: нужны маршруты (`ip route`, пакет `ip-full` из Entware) — механика та же, что в [openwrt.md](openwrt.md#5-файрвол-и-маршрутизация).

## 7. Если не работает

| Симптом | Что проверить |
|---------|---------------|
| После перезагрузки служба не поднялась | `opkg print-architecture` (правильный ли пакет), `/opt/etc/init.d/S99usque status`, `/opt/var/log/usque.log`. Убедитесь, что накопитель с Entware примонтирован в `/opt`. |
| `нет /opt/etc/usque/config.json` | Выполните `usque -c /opt/etc/usque/config.json register` (или скопируйте конфиг с другого устройства). |
| `CONNECT_TIMEOUT` в журнале | Ни одна комбинация не подключилась: проверьте обход (раздел 5), попробуйте `check --bypass --all`, смените `--bypass-sni`, увеличьте `--connect-timeout`. |
| Прокси не виден с компьютера | В `usque.conf` должен быть `BIND=0.0.0.0` и перезапуск службы; проверьте `netstat -lntp | grep 1080` на роутере. |
| Роутер стал медленнее | Режимы `socks`/`http-proxy` эмулируют стек в памяти процесса — на слабых моделях выбирайте `l4-socks`/`l4-http-proxy`. |

## 8. Удаление

```sh
/opt/etc/init.d/S99usque stop
opkg remove usque
```

Пакет не удаляет `/opt/etc/usque` (там лежат `config.json` и `usque.conf` и могут быть ваши правки) — удалите папку вручную, если она больше не нужна.

Сборка пакетов — `scripts/build-keenetic.sh`, workflow на GitHub — "Build Keenetic ipk" (запускается вручную или автоматически вместе с релизом).
